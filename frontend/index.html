Pruszkow News Pipeline connects to your Gmail inbox, fetches emails, sends them to an AI provider (Gemini, Claude, or OpenAI) to generate polished news articles, and creates Gmail drafts with the results. The entire workflow is a 3-step pipeline handled from a single page.

The app has three main pages, accessible from the sidebar:

  • Pipeline — The main workspace. Fetch emails, select them, generate articles, and create drafts.
  • Dashboard — Usage statistics, quota tracking, and recent activity.
  • Settings — Gmail connection, AI provider configuration, and article generation options.

Before using the pipeline, you need to complete three setup steps in the Settings page. Follow each step in order — each one depends on the previous.

A

Get Google OAuth Credentials (client_secret.json)

This file tells Google that your app is allowed to access Gmail on your behalf. You only need to do this once.

A1. Go to Google Cloud Console

Open console.cloud.google.com in your browser and sign in with your Google account.

A2. Create or select a project

At the top-left of the page, click the project dropdown (next to "Google Cloud"). Either select an existing project or click New Project, give it a name (e.g., "Pruszkow News Pipeline"), and click Create. Make sure the new project is selected in the dropdown.

A3. Enable the Gmail API

In the left sidebar, go to APIs & Services → Library. Search for "Gmail API", click on it, then click Enable. This grants your project permission to use Gmail's API.

A4. Configure the OAuth Consent Screen

Go to APIs & Services → OAuth consent screen.

  • Choose External user type (unless you have a Google Workspace account, in which case choose Internal). Click Create.
  • Fill in the App name (e.g., "Pruszkow News Pipeline").
  • Enter your User support email (your own email).
  • Under Developer contact information, enter your email again.
  • Click Save and Continue.
  • On the Scopes page, click Add or Remove Scopes, search for gmail.modify, select it, click Update, then Save and Continue.
  • On the Test users page, click Add Users and enter the Gmail address you want to use with the pipeline. Click Add, then Save and Continue.
  • On the Summary page, click Back to Dashboard.

Note: While the app is in "Testing" mode, only test users can authorize it. You can add up to 100 test users.

A5. Create OAuth 2.0 Client ID

Go to APIs & Services → Credentials.

  • Click + Create Credentials at the top, then select OAuth client ID.
  • For Application type, select Desktop app (or "Other" if Desktop isn't shown).
  • Give it a name (e.g., "Pruszkow Pipeline Desktop").
  • Click Create.

A6. Download the JSON file

After creating the client ID, a popup shows your Client ID and Client Secret. Close the popup. You'll now see your new client listed under OAuth 2.0 Client IDs.

  • Click the download icon (down-arrow) next to your client name.
  • A JSON file will be downloaded. It will be named something like client_secret_XXXXX.apps.googleusercontent.com.json.
  • Rename this file to client_secret.json.

A7. Upload to the app

Go to Settings → Google Credentials in the app. Click Choose JSON File, select the client_secret.json file you just downloaded, then click Upload & Save. A green "Credentials file found" message confirms success.

B

Connect Gmail

In Settings → Gmail Connection, click Connect Gmail. This opens a Google OAuth consent screen in your browser.

  • Select the Gmail account you added as a test user in step A4.
  • If you see "This app isn't verified", click Advanced → Go to [your app name] (unsafe).
  • Click Allow to grant the app access to read and modify your Gmail.
  • You'll be redirected back to the app.

After returning, the sidebar footer will show a green dot with "Gmail connected".

C

Get an AI Provider API Key

You need at least one API key for article generation. Choose one of the three providers below. You can add more later and switch between them.

C1. Google Gemini (Recommended, Free Tier Available)

  • Go to aistudio.google.com/apikey.
  • Sign in with your Google account if prompted.
  • Click Create API Key.
  • Select a Google Cloud project (use the same one from step A2, or create a new one).
  • Click Create API Key. Your key will be displayed.
  • Copy the key (it starts with AI).

In the app, go to Settings → AI Provider. Select Google Gemini, paste your key into the input field, click Save, then Test. A green "Connected. Model: ..." message means it works.

C2. Anthropic Claude

  • Go to console.anthropic.com.
  • Sign up or log in to your Anthropic account.
  • Go to API Keys in the left sidebar.
  • Click Create Key, give it a name (e.g., "Pruszkow Pipeline"), and click Create.
  • Copy the key immediately (it starts with sk-ant-). You won't be able to see it again.

In the app, go to Settings → AI Provider. Select Anthropic Claude, paste your key, click Save, then Test.

C3. OpenAI

  • Go to platform.openai.com/api-keys.
  • Sign up or log in to your OpenAI account.
  • Click Create new secret key.
  • Give it a name (e.g., "Pruszkow Pipeline") and click Create secret key.
  • Copy the key immediately (it starts with sk-). You won't be able to see it again.
  • Note: OpenAI requires a paid account and billing setup. Check your usage at platform.openai.com/usage.

In the app, go to Settings → AI Provider. Select OpenAI, paste your key, click Save, then Test.

After testing, click Save Provider at the bottom to activate your chosen provider.

This is the first step of the workflow. It pulls emails from your connected Gmail inbox into the app.

Max emails

A number input that controls how many emails to fetch in one go. Default is 10. You can set it between 1 and 100. The app requests this many emails from Gmail, but may return fewer if your inbox has fewer unread messages matching the filter.

Filter

A dropdown that narrows which emails are fetched from Gmail:

  • All emails — Fetches every email in your inbox regardless of read status.
  • Unread only — Only fetches emails you haven't opened yet. Useful for processing new incoming messages.
  • Read only — Only fetches emails you have already read. Useful for processing older content.

Mark as read

A checkbox. When checked, every email that is fetched will be automatically marked as read in Gmail. This helps keep your inbox clean — after processing, fetched emails won't appear as unread anymore. If unchecked, emails remain in their current read/unread state.

Add "listed" label

A checkbox. When checked, the app creates a Gmail label called "listed" and applies it to every fetched email. This lets you easily find in Gmail which emails have already been processed by the pipeline. You can later filter by this label in Gmail to see your history.

Fetch Emails button

Click this button to start fetching. The button text changes to "Fetching..." while the request is in progress. Once complete:

  • The log panel (right side) shows how many emails were fetched and how many were new.
  • The email list appears in Step 2 below.
  • Step 2 becomes enabled (no longer grayed out).

If the fetch fails (e.g., Gmail not connected), an error message appears in the log panel.

After fetching, this step shows all retrieved emails. You select which ones to send to the AI for article generation.

Email list

A list of all fetched emails. Each email shows:

  • A checkbox — Check it to include the email in article generation.
  • The subject line (title).
  • The sender name/email.
  • The date the email was received.

Click anywhere on an email row (except the checkbox) to open a preview.

Email preview

Clicking an email opens a preview panel below the list showing:

  • The full subject.
  • The sender and date.
  • The full email body text.
  • Any attachments (shown as filename tags).

Click Close to dismiss the preview.

Select All

A checkbox at the top of the list. When checked, it selects every email in the list at once. When unchecked, it clears all selections. Individual checkboxes can still be toggled independently.

"X selected" badge

Displays the current number of selected emails (e.g., "3 selected"). Updates in real time as you check/uncheck emails.

Generation mode toggle

Two radio buttons that control how the AI processes your selected emails:

  • All in one (Batch) — Sends all selected emails to the AI in a single API call. Uses fewer tokens and one system prompt. Faster and cheaper, but if the AI response fails, all articles are lost. Best for 2–5 similar emails.
  • One by one (Sequential) — Processes each email individually in separate API calls. Each article is independent — one failure doesn't affect others. Results appear progressively. Uses more tokens (system prompt repeated per email). Best for many diverse emails.

The ⓘ info icon next to the toggle opens a modal with a side-by-side comparison of both modes.

Note: When only 1 email is selected, batch mode is automatically disabled and one-by-one is forced (batch is pointless for a single email).

Generate Articles button

Click to send the selected emails to the AI. The button is disabled until at least 1 email is selected. While generating:

  • The button text changes to "Generating..."
  • Log entries appear in real time showing progress.
  • Step 3 becomes enabled.

Once generation finishes, the articles appear in Step 3 for review.

The final step. AI-generated articles are displayed here for review, editing, and optional draft creation in Gmail.

"X articles" badge

Shows the total number of articles that were successfully generated.

View toggle: Cards / JSON

Two buttons that switch how articles are displayed:

  • Cards (default) — Each article is shown as an editable card with a headline input, a body textarea, metadata, and a download button.
  • JSON — All articles are shown as raw JSON. Useful for debugging or copy-pasting structured data.

Article card (Cards view)

Each generated article appears as a card containing:

  • Checkbox — Select/unselect this article for draft creation.
  • Headline input — The AI-generated headline. You can edit it directly by clicking and typing. Changes are saved locally.
  • Body textarea — The full AI-generated article text. Editable — click and modify the content before creating drafts.
  • Filename — The suggested filename shown in the footer.
  • Download button — Click to download the article as a file.

Select All (articles)

A checkbox that selects or deselects all articles at once. Toggling it clears individual selections and re-selects all (or none).

Create Drafts button

Creates Gmail draft emails from the selected articles. The button text shows the count, e.g., "Create Drafts (3)". Disabled when no articles are selected.

Each selected article becomes a separate Gmail draft. The draft contains the article headline as the subject and the article body as the email body. Results appear in the log panel: green for successful drafts, red for failures.

The Dashboard tracks your API usage across all pipeline runs. It loads automatically when you navigate to this page.

Summary cards (top row)

Four cards showing total API request counts:

  • Today — Requests made today (resets at midnight).
  • This Week — Requests made this week.
  • This Month — Requests made this calendar month.
  • Total — All-time total requests since usage tracking began.

Token usage cards (second row)

Four cards showing token consumption:

  • Today Tokens — Tokens used today.
  • Week Tokens — Tokens used this week.
  • Month Tokens — Tokens used this month.
  • Avg Latency — Average response time per API request in milliseconds.

Tokens are displayed with abbreviations: "k" for thousands (e.g., 12.5k), "M" for millions.

Quota Usage bars

Six progress bars showing current usage against your configured limits:

  • Daily Requests, Weekly Requests, Monthly Requests
  • Daily Tokens, Weekly Tokens, Monthly Tokens

Each bar shows "current / limit" (e.g., "45 / 100"). If no limit is set, it shows "current / unlimited" with an empty bar. Bar colors:

  • Purple — Under 80% of limit.
  • Yellow — 80% or more of limit (warning).
  • Red — 100% or more of limit (over).

Reset timers show when each quota period resets (e.g., "resets in 14h 32m").

Requests by Status

Two rows showing:

  • Successful (green dot) — Total API calls that returned a valid response.
  • Failed (red dot) — Total API calls that errored out.

By Provider

Lists each AI provider you've used (Gemini, Claude, OpenAI) with stats:

  • Number of requests made to that provider.
  • Total tokens consumed.
  • Number of failed requests.
  • An "ACTIVE" badge on the currently selected provider.

If no API calls have been made yet, shows "No API calls yet."

Recent Activity table

A table of the last 50 API requests, showing:

  • Time — When the request was made (e.g., "Aug 27, 14:32").
  • Provider — Which AI service was used.
  • Operation — What was done (e.g., "generate").
  • Tokens — Total tokens for that request.
  • Latency — How long the request took (e.g., "2340ms").
  • Status — "OK" (green) or "FAIL" (red).

Most recent entries appear at the bottom. The table scrolls horizontally on narrow screens.

Quota Limits form

Set soft limits for your own reference. These do not block API calls — they only affect the progress bars above. Set to 0 for unlimited.

  • Daily Requests, Weekly Requests, Monthly Requests
  • Daily Tokens, Weekly Tokens, Monthly Tokens

Click Save Limits to apply. Click Reset All Usage to wipe all usage data (requires confirmation — this cannot be undone).

Configure everything the pipeline needs to operate. Organized in two columns.

Left column

Gmail Connection

Shows whether your Gmail account is connected. Click Connect Gmail to start the OAuth flow. After authorizing, the status updates to "Connected to Gmail" (green). The sidebar footer dot also turns green.

Google Credentials

Upload the OAuth 2.0 JSON file from Google Cloud Console. This is the file you downloaded in the First-time setup guide (step A6).

  • Click Choose JSON File to select the client_secret.json file.
  • Click Upload & Save.
  • Status shows "Credentials file found" (green) or "No credentials file found" (red).

The file must be a valid Google OAuth 2.0 client secret JSON. It contains your Client ID, Client Secret, and redirect URIs. This file is stored locally and never leaves your machine.

AI Provider

Three providers are listed as radio buttons. Each has its own key input, save button, and test button:

  • Google Gemini — Free tier available. Get your key at aistudio.google.com/apikey. Key starts with AI.
  • Anthropic Claude — Paid. Get your key at console.anthropic.com. Key starts with sk-ant-.
  • OpenAI — Paid. Get your key at platform.openai.com/api-keys. Key starts with sk-. Requires billing setup.

For each provider: paste your API key, click Save to store it, then click Test to verify. Success shows "Connected. Model: ..." (green). Failure shows the error message (red).

After saving a key, click Save Provider at the bottom to set which provider is active. Only one provider can be active at a time. You can configure multiple providers and switch between them.

Right column

Ignored Senders

Emails from these senders are hidden from the pipeline (not fetched). Uses substring matching:

  • Type an email address or domain (e.g., "linkedin.com") and click Add.
  • "linkedin.com" will block all emails containing "linkedin.com" in the sender field (e.g., noreply@linkedin.com, jobs@linkedin.com).
  • Press Enter in the input field as a shortcut for Add.
  • Click the × button next to any entry to remove it from the ignore list.

System Prompt

The instructions sent to the AI for every article generation. Controls the tone, language, format, and rules the AI follows. The textarea is pre-filled with the current prompt. Edit it and click Save Prompt. The prompt cannot be empty.

Article Settings

Fine-tune article generation parameters:

  • Min words — Minimum word count for generated articles (default: 50). Shorter emails may produce fewer words.
  • Max words — Maximum word count, enforced by the AI prompt (default: 200).
  • Article language — Choose Polish, English, or Auto (based on the email's language).
  • Default generation mode — Sets which mode (batch or one-by-one) is pre-selected in the Pipeline page.

Click Save Settings to apply. Min words cannot exceed max words.

Always visible on the right side of every page. Shows real-time log messages as you use the app:

  • Gray — Informational messages.
  • Green — Success messages (e.g., "Fetched 5 emails", "Draft created").
  • Red — Error messages (e.g., "Fetch failed", "Auth error").
  • Yellow — Progress messages (e.g., "Generating 3 article(s)...").

Click Clear to remove all log entries.

Generation Mode

All in one (Batch)

  • Uses 1 API call regardless of email count
  • System prompt sent only once
  • Lower token usage overall
  • Best for staying within quota limits
  • If AI response fails or is malformed, all articles are lost
  • AI may occasionally mix up content between emails
  • Longer wait before seeing any results

One by one (Sequential)

  • Each article is independent — one failure doesn't affect others
  • Results appear progressively as each finishes
  • More reliable for mixed content types
  • Uses N API calls for N emails
  • System prompt repeated for every email
  • Consumes quota faster
Tip: For 2–5 similar emails, batch mode saves the most quota. For many diverse emails, one-by-one is safer.
